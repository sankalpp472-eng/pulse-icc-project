What you are looking at

An LLM agent solves airline customer-service tasks by calling 14 MCP tools. Each tool is its own serverless function on Knative and scales to zero when idle, so the next call pays a cold start (~1.5–2.5 s while a pod starts).

Pulse sends the predictor a hint before every LLM step: the tools called so far plus a few numbers about the conversation (no raw text). The predictor (LightGBM by default) ranks the next action: one of the 14 tools, or RESPOND (the agent answers the customer). Every tool with probability ≥ θ becomes a PrewarmRequest. The controller pings it, so Knative starts the pod while the agent is still thinking. With fan-out it starts k pods for k parallel lookups.

  1. Live agent: a real LLM agent. The customer is an LLM playing a tau-bench task, or you.
  2. Replay recorded: the tool calls of a recorded tau-bench conversation, with seeded think and customer-reply gaps. The same input every time, so it is fair to compare C0 and C3.
  3. Simulated cluster: pods, cold starts (measured per tool on EKS), the 60 s idle window and prewarming, all on the laptop. Knative uses the real cluster in your kubectl context (kind or EKS).

Configurations: C0 = scale to zero, no prewarming · C1 = always warm (min-scale 1) · C3 = scale to zero + predictor + controller.

Monitoring (Knative mode): Prometheus scrapes the predictor, the prewarm controller, the replay runner, the tools' pods (kube-state-metrics) and the nodes; Grafana's dashboards (infra/monitoring) show them live in the Monitoring tab, for the running episode or run, or for any finished run from Results.

The cloud around it:

  • Load tests (Experiments → Load test): Locust and asyncio drive the predictor, the tools or whole episodes harder and harder.
  • Model registry + retraining (Models tab): pulse-v3's model and the lightgbm + markov model are versioned in S3. Retraining (here or as a Kubernetes Job) publishes a new version that becomes the latest only if it beats the current one on held-out tasks.
  • Infrastructure as code: Terraform makes the S3 registry, ECR, the CI roles and, optionally, the EKS cluster.
  • CI/CD + GitOps: GitHub Actions test the code and build the image; Argo CD makes the cluster follow Git (top bar: commit, sync status).

Tip for a demo: reset the cluster (side panel), run a task with None (C0), reset again, run the same task with the predictor. Then compare the two rows in Episodes so far.
